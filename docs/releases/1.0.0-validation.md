## Real Qwen3 CLI checks

The packaged CLI loaded Qwen3-1.7B on Metal with BF16 weights and activations,
a 3 GiB Java heap, `--thinking`, and a 512-token limit for these checks:

- Chat streamed reasoning and completed `17 × 23 = 391`.
- Agent mode streamed reasoning, requested approval for `/bin/pwd`, executed the
  approved command once, and reported the isolated test directory correctly.
- Both processes exited cleanly. The process guards reported no additional swap-outs.

Portable tests cover the flag, interactive on/off toggles, unsupported models,
settings and alternatives, incomplete reasoning, split markers, Unicode and
terminal-control filtering. Agent tests retain approval requirements and exclude
reasoning from saved tool-call history.

The real-model check found and corrected a CLI shutdown allocation bug. Closing
Qwen chat now discards the CLI-owned GPU weight bindings before normal backend
cleanup. A Metal regression checks that discarded weights remain unmaterialized,
other live tensors retain their values, and closing twice is safe.

## Desktop and artifacts

The Images status label is removed. Image settings, generation, scrolling and

Core, ONNX and distributed binary, source and Javadoc JARs were packaged at

checked through their package phase; publication uses the separate deploy phase.

Tensor arithmetic, autograd, optimizer and training implementations are unchanged.

## Refreshed GitHub downloads

The refreshed 1.0.0 GitHub assets include the later sampler correctness and
bounded-video performance fixes, plus a standalone Apple Silicon desktop JAR.
The desktop profile bundles JavaFX, video codecs and the chat/agent dependencies.
CI builds both executable JARs and checks their entry points and native resources.

The standalone desktop JAR launches without Maven or a separate JavaFX install.
An isolated check generates five 16×16 fixture frames through its spawned video
worker in FP32, FP16 and BF16, writes MP4s and decodes their first frames with the
bundled codec. No long pretrained generation is required for this packaging check.

CPU loading of Frisky exposed an initialization-inspection error for column-major
weight slots. Raw array access now requires a full contiguous allocation; views
use the existing logical value path. A strengthened regression forces strided
loading slots in all five decoder families and three dtypes, preserves every
restored parameter, and rejects unnecessary initialization scaling. The FP32
cases reproduce the error before the guard and pass afterward. The fix changes
initial parameter inspection, leaving forward, backward and optimizer math intact.

The Frisky desktop screenshot renders the original saved README conversation
through the current production WebView. All three prompts and recorded replies
retain their exact text and capitalization. [Capture provenance](../frisky-ui-capture.json).
The other model examples use the same downloadable desktop JAR.

## Desktop execution and image previews

Desktop execution is selected at startup with `--backend auto`, `--backend cpu`,
or `--backend metal`. The Settings control and persistence bridge are removed.
Argument tests cover both flag forms, invalid values and model reloads. CPU
service checks cover Qwen, Gemma, DeepJ checkpoints and the spawned video worker.

Generated previews retain their pixels in a canvas independently of WebKit's
decoded image cache. Pixel checks cover multiple images, scrolling, garbage
collection and canvas-context restoration. PNG downloads still use the original
encoded bytes. These checks use fixtures and a previously generated fox image,
without running another pretrained generation.

The README's Frisky card showcases the CLI and its original screenshot, with a
short desktop link. The Qwen and image cards link briefly to CLI access.
All changes in this refresh are confined to desktop presentation, desktop backend
selection, documentation and their tests; model and training calculations are
unchanged.

## Combined desktop download

The combined desktop profile packages the macOS ARM64 and Windows x64 JavaFX
libraries in the same JAR. Platform-specific native filenames remain distinct,
and only those two JavaFX classifiers enter the combined archive. The normal
`desktop` profile retains host-specific source builds.

Mac packaging checks launch the actual desktop window using JavaFX from the
packaged JAR, render a tiny PNG, and check chat, image and video controls, with startup backend selection.
The archive checks require both sets of windowing and WebView libraries. Desktop
startup checks platform compatibility before probing Metal. Model, tensor,
autograd, native-kernel and training calculations are unchanged.
